## 1. 白描技法

白描就是：**用细节代替概括，用事实代替形容词。**

好的工作文档不需要形容词，只需要把看到的东西如实写下来。

### 怎么做到

- 不用"存在一定风险"，写"如果周五前跑不完数据校验，上线后历史记录会缺"。
- 不用"近期用户反馈较多"，写"过去三天工单量涨了 40%，集中在登录超时"。
- 不用"性能有待优化"，写"首页加载时间 4.2 秒，比上个月慢了 1.5 秒"。
- 不用"团队配合良好"，写"上周三个需求均按时交付，没有返工"。

### 为什么要这样做

概括性形容词是写作者偷懒的信号。你说"存在一定风险"，读者不知道是多大的风险、要不要现在处理、是不是你夸张了。但你说"如果周五前跑不完数据校验，上线后历史记录会缺"，读者自己就能判断严重程度。

**白描不要求文笔华丽，只要求你把自己看到的、知道的如实写下来。**

### 反面示例

| 概括写法 | 白描写法 |
| --- | --- |
| 当前系统稳定性存在一定隐患 | 上个月 P0 故障 2 次，P1 故障 5 次，均集中在支付链路 |
| 用户满意度有所下降 | NPS 从 42 降到 31，投诉集中在退款流程超过 3 天 |
| 团队人手较为紧张 | 前端 2 人同时扛 3 条业务线，本月已出现 2 次排期冲突 |
| 竞品动作频繁 | 竞品 A 上周上线了会员体系，竞品 B 本月降价 30% |

### 白描不是"写更多"

白描不意味着把所有细节都堆上去。只写和当前决策、当前判断相关的细节。和主题无关的细节，再具体也是噪音。

## 2. 判断力

判断力是"人味"的核心。机器能整理信息，但只有人能做判断。

### 判断 vs 信息

有信息、无判断：

```
当前版本用户留存率为 45%，竞品 A 留存率为 52%，竞品 B 留存率为 48%。
```

有信息、有判断：

```
当前版本留存 45%，比竞品 A 低 7 个百分点。我判断差距主要来自我们的新手引导太弱——前 3 天流失了 40% 的用户。如果下半年只做一件事，应该做新手引导。
```

### 怎么写出判断

- 用"我判断""我倾向于""我看下来"开头。不要躲在"我们认为"后面。
- 每个判断跟一个理由。不需要长篇论证，但要说"因为什么"。
- 不确定就说"我还不确定""还在验证""目前有两种可能，我倾向于 A"。
- 不同意就说"我不太同意""我有顾虑""我的担心是……"。

### 判断的安全边界

- 判断基于事实，不基于猜测。"我感觉"不如"从数据看"。
- 专业领域内的判断直接写，不需要铺垫。你是这个领域的专家，你的判断就是读者的信息源。
- 超出自己专业范围的，诚实说"这块我不专业，建议找 XX 确认"。

### 反面示例

| 无判断 | 有判断 |
| --- | --- |
| 经综合评估，方案 A 较为合适 | 我倾向于方案 A。B 依赖的外部接口不稳定，C 排期多两周。A 不完美，但能本周上线 |
| 当前存在两种不同意见 | 目前有两种看法：产品想先跑通流程，研发想先做架构。我倾向于先跑通流程，因为架构可以边跑边改 |
| 建议后续持续关注 | 我不确定这个方向对不对，建议先跑两周实验，看留存再决定 |

## 3. 节奏感

节奏感让文档可读。一段全是长句，读者喘不过气；一段全是短句，读者觉得你在喊口号。

### 基本原则

- **短句做判断，长句给细节。**
- 三句短句之后可以接一句长句展开。
- 一段不要超过 5 行。
- 一段只讲一件事。

### 示例

没有节奏：

```
当前服务已经完成核心功能开发，测试环境已部署并通过冒烟验证，预计下周启动联调，联调结束后将进入灰度阶段，灰度期间会持续监控核心指标，若指标正常则全量发布。
```

有节奏：

```
核心功能开发已完成。

测试环境也部署了，冒烟全部通过。下周开始联调，联调结束后进入灰度。

灰度期间重点看三个指标：响应时间、错误率、QPS。如果都正常，就全量。如果指标异常，立刻回滚，先排查原因再决定下一步。
```

### 怎么练

写完一段之后，读出来。如果一口气读不完，这段就该拆。如果读起来像念经——每句一样长、一样平淡——就需要把某句缩短或拉长。

### 标点也能造节奏

- 句号是硬停顿，逗号是软停顿。
- 一连串逗号让人喘不过气，该用句号就用句号。
- 分号在中文工作文档里没什么用，直接用句号或逗号。

## 4. 诚实

诚实比正确更重要。AI 味的核心特征是"永远自信、永远完整、永远正确"——而这恰恰是活人最不可能做到的事。

### 诚实清单

- 不知道就说不知道。"这个数据我还没拿到，明天补上。"
- 不确定就说"还在验证""目前看是 A，但还需要 B 的数据确认"。
- 有分歧就说"我和 XX 看法不同，分歧在于……"。
- 做错了就说"这个判断我当时错了，原因是我忽略了……"。
- 不会就说"这块我不懂，需要找 XX 来写"。

### 诚实不是自我贬低

诚实是"我的判断基于这些信息，信息可能有遗漏"，而不是"我水平不行"。前者是专业，后者是自卑。

### 反面示例

| 不诚实（AI 腔） | 诚实 |
| --- | --- |
| 该方案技术可行性较高，风险可控 | 技术上能实现，但我不确定性能是否扛得住。下周先做压测 |
| 团队整体状态良好，项目稳步推进 | 项目进度正常，但前端的同学连续加班两周了，这个节奏不可持续 |
| 综合各维度评估，建议推进 | 我没想清楚，但截止时间到了。先说我的倾向，如果不对再调整 |

## 5. 删 AI 腔

AI 腔不只是用词问题，本质是**写作者隐身**。当读者读不出"谁写的、怎么想的、为什么这么判断"，就是 AI 腔。

### 高频替换对照

| AI 腔 | 人腔 |
| --- | --- |
| 经评估，我们认为…… | 我判断…… / 看下来，…… |
| 建议可以考虑…… | 建议…… / 我认为应该…… |
| 后续需要进一步推进…… | 下一步：…… |
| 值得关注的是…… | （直接写关注什么、为什么） |
| 综上所述…… | （删掉，结论自己站得住） |
| 从整体视角来看…… | （删掉，直接说事） |
| 在某种程度上…… | （删掉，或者写具体程度） |
| 不可否认的是…… | （删掉，或者写"有一个问题必须承认：……"） |
| 众所周知…… | （删掉。如果真的众所周知，你不需要写这四个字） |
| 需要指出的是…… | （删掉，直接指出来） |
| 以期达到…… | 为了…… / 目标是…… |
| 进行了相关优化工作 | 优化了……（具体写什么） |
| 呈现出……态势 | （直接用动词：涨了 / 降了 / 稳定在） |
| 赋能 / 抓手 / 闭环 / 拉齐 / 对齐 / 沉淀 | 换成具体动作：提供了工具 / 切入方式 / 从开始到结束的流程 / 同步信息 / 确定口径 / 记录下来 |

### 三个自检问题

写完一段后，问自己：

1. 这句话如果是我在会议室里口头说的，我会这么说吗？不会就改。
2. 删掉全部形容词，这句话还站得住吗？站不住就补事实。
3. 读者读完这一段，能说出"写作者的观点是什么"吗？说不出就补判断。

## 6. 口语化边界

"有人味"不等于"像聊天"。工作文档需要专业感，但不需要机构腔。

### 可以做的

- 用"我"和"你"，不用"笔者"和"读者"。
- 用"因为"不用"由于"，用"但是"不用"然而"，用"如果"不用"倘若"。
- 用"先""再""然后"连接时间顺序，不用"首先""其次""继而"。
- 用"比如"不用"例如"，用"或者"不用"抑或"。
- 用"要看"不用"取决于"，用"大概率"不用"较大概率"。

### 不要做的

- 不要用网络流行语、表情包、梗。工作文档的寿命比流行语长。
- 不要用"讲真""说实话""你懂的"这类口头禅。口头禅放在口语里很自然，落成文字就显得轻浮。
- 不要用"简直""超级""巨"这类程度副词。用事实代替强调。
- 不要在正式方案里用"搞""弄""整"这类万能动词。它们不精确。

### 灰度判断

口语化的边界取决于文档类型和受众：

- 纪要、周报、同步：可以更口语化，像在跟同事说话。
- 方案、提案、决策文档：语气更正式，但判断仍然直接、主语仍然明确。
- 公告、通知：语气正式，但不用模板腔。
- 复盘：诚实优先，格式从简。

如果你不确定某句话的口语化程度是否合适，读一遍。如果读起来像在跟老板汇报时说的，就可以。如果读起来像在酒桌上说的，就太过。
