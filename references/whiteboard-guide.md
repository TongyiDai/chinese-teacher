# 画板使用指南

用飞书画板在文档的关键节点上做视觉摘要。画板不是装饰，是文字的"视觉浓缩"——每个画板只承载 5-7 个信息单元，用形状 + 文字 + 箭头，简单直接。

## 什么时候用

**默认行为。** 用 chinese-teacher 写文档时，自动在三个节点插入画板，不需要用户额外指定。如果画板生成失败（如 lark-cli 未认证），fallback 为纯文字文档，不阻塞。

## 三个插入节点

### 1. 文档开头：封面页

画板放在文档标题下方，相当于封面。内容：**标题 + 一句话核心结论**。让读者 5 秒内理解这个文档在说什么。

示例内容：
- 方案："People AI 解决方案" + "从招聘到绩效，用 AI 重构 HR 全链路"
- 周报："Q3 第 5 周进展" + "数据校验通过，本周四上线"
- 纪要："产品评审会纪要" + "确定 A 方案，下周三前出原型"

### 2. 关键章节：核心框架

画板放在文档最重要的章节中。内容：**该章节的核心框架、关键数据或对比**。常见形式：

- Before/After 对比（两列，左右对比）
- 数字卡片（大号数字 + 简短说明）
- 流程箭头（A → B → C → D）
- 框架图（2×2 矩阵或三层金字塔）

选择哪一种，取决于该章节最核心的信息形态。不是每个章节都放，只放最有表达力的那一个。

### 3. 文档结尾：行动召唤

画板放在文档末尾。内容：**核心结论复述 + 下一步行动**。让读者记住最重要的 1-2 件事，知道出去之后要做什么。

示例内容：
- "核心结论：数据校验通过，本周四上线" + "你需要做：周五前完成回归测试"
- "三个待决策项" + "Owner + 截止时间"

## 画板内容原则

1. **画板不重复文字。** 画板是文字的"视觉摘要"，不是把文字复制过去。如果一句话文字已经说清楚了，画板就不要再写一遍。
2. **每个画板不超过 5-7 个信息单元。** 一个信息单元 = 一个标题 + 一行说明，或一个数字 + 一个标签，或一个流程节点。
3. **用形状，不用图表。** 矩形、圆角矩形、圆形、箭头。不要做复杂的柱状图、饼图、雷达图。
4. **颜色从风格中来。** 每个画板风格自带完整的配色方案，不要自己调色。
5. **画板是"可编辑的"。** 生成的是飞书原生画板，不是截图。用户可以在飞书里继续改文字、调位置、换颜色。

## 文风 → 画板风格映射

画板风格跟随文档文风，从内嵌的 24 种风格中选取（源自 zara 的 [beautiful-feishu-whiteboard](https://github.com/zarazhangrui/beautiful-feishu-whiteboard)，已内嵌到本 skill 的 `whiteboard/` 目录）：

| 文风 | 画板风格 | Formality | Vibe |
|------|---------|-----------|------|
| 默认风格 | **Riso Brut**（默认首选） | Medium | 干净、专业、不抢眼 |
| | Neo-Grid Bold | Medium | 结构化、编辑感 |
| | Linen Cut | High | 沉稳、经典 |
| 同事风格 | **Cut Bloom**（默认首选） | Medium | 温暖、柔和、有活力 |
| | Apricot Arc | Medium | 亲切、几何感 |
| | Cobalt Bloom | Medium | 自信、有表达力 |
| 咨询风格 | **Reading Room**（默认首选） | High | 克制、权威、机构感 |
| | Cobalt Glaze | High | 精致、冷静 |
| | Jade Lens | High | 和谐、专业 |
| 精神病风格 | **Riptide Cobalt**（默认首选） | Medium | 大胆、海报感、冲击力 |
| | Specimen Bold | Low | 字体感、图形化 |
| | BlockFrame | Low | 极繁、拼贴感 |

**选择逻辑**：
1. 先选文风对应的默认首选风格
2. 如果用户对视觉有偏好，在同文风的 2-3 个候选中切换
3. 生成后告知用户"画板用了 XX 风格，可以随时切换"

## 每种文档类型的画板策略

| 文档类型 | 开头画板 | 关键章节画板 | 结尾画板 |
|---------|---------|------------|---------|
| 方案/提案 | 主题 + 核心结论 | 方案对比（Before/After）或关键设计框架 | 决策要点 + 下一步 |
| 周报 | 项目名 + 本期核心变化 | 风险/阻塞可视化（事项 + 影响 + 状态） | 下周重点 |
| 纪要 | 会议主题 + 核心结论 | 关键讨论点框架 | Action items（Owner + 截止时间） |
| 公告 | 变更事项 + 影响范围 | 具体变化对比 | 读者需要做什么 |
| 复盘 | 事件 + 结论摘要 | 根因分析框架 | 改进项 |

## 生成流程

```
1. 确定文风 → 映射画板风格（从上表选默认首选）
2. 确定文档类型 → 确定三个画板的内容（从上表取策略）
3. 逐一生成画板：
   a. 读取 `whiteboard/CATALOG.md` 确认风格存在
   b. 读取 `whiteboard/templates/<slug>/design.md` 获取配色方案
   c. 读取 `whiteboard/RULES.md` 获取画板硬限制
   d. 生成 SVG，渲染检查，写入飞书画板
   e. 获取画板链接
4. 将画板链接插入文档对应位置
5. 告知用户画板风格，可随时切换
```

## 画板生成失败的 fallback

如果 `lark-cli` 未安装或未认证，画板生成会失败。此时：
- 不阻塞文档生成
- 在文档中标注"此处可插入画板"（但不写死占位符）
- 在回复中告知用户"画板生成需要 lark-cli 认证，当前跳过"

## 与其他 skill 的关系

- **画板能力内嵌**：24 种配色风格和画板生成规则已内嵌到本 skill 的 `whiteboard/` 目录，源自 zara 的 [beautiful-feishu-whiteboard](https://github.com/zarazhangrui/beautiful-feishu-whiteboard)（MIT 许可）。不需要额外安装。
- **lark-doc**：在文档中插入画板时，通过 lark-doc 的 block 操作将画板嵌入文档。
- **lark-whiteboard**：如果用户需要单独编辑画板，切到 lark-whiteboard skill。
